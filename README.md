# tube-template

A video site from a folder of videos: HLS streaming with a quality menu, hover previews, categories, search,
likes and comments, ad slots, French or English UI. One config file, one CLI (`./tube`), one box. It stays
**private by default** (basic auth, noindex) until you open it.

Stack: Node 24 (Fastify SSR) + Postgres 17 + nginx in docker compose; ffmpeg for the pipeline; any S3-compatible
bucket for media; OVH Public Cloud (fully automated) or any Ubuntu server over SSH.

## Quickstart

```bash
gh repo create my-niche --private --template yourimerad/tube-template --clone && cd my-niche
./tube init                      # wizard: name, language, colour, videos folder, hosting target
./tube demo                      # or put your own videos in the folder you chose: <folder>/<Category>/<video>.mp4
./tube ingest                    # HLS ladder + posters + previews into out/
./tube dev                       # http://127.0.0.1:18190 (prints the local user + throwaway password)
./tube up && ./tube deploy       # create the box and put the site online (https://<ip>.sslip.io, private)
```

`./tube help` lists every command. `./tube test` runs the curl checks and the Playwright e2e against the dev site.

Requirements on your machine: Node 24+, docker (with compose), ffmpeg/ffprobe on PATH (or `FFMPEG_BIN_DIR=/path/to/bin`),
`jq`, `rsync`, `curl`, `ssh`, `openssl`. Nothing else is installed globally: rclone, k6, certbot and Playwright run
from pinned docker images.

## Your videos

```
videos/
  Cooking tips/
    how_to-boil eggs.mp4          -> category "Cooking tips" (/c/cooking-tips), title "How to boil eggs"
    Pasta 101.mov
  Outtakes/
    take-3.mp4
  intro.mp4                       -> category videos.default_category
```

- Each subfolder is a category; folder name -> display name, slug derived from it (accents and spaces are fine).
- Titles come from file names: `-` and `_` become spaces, the first letter is capitalised.
- Optional manifest (`videos.manifest`), CSV or JSON, keyed by the relative path (`Cooking tips/Pasta 101.mov`) or
  the file name alone. CSV columns: `path,title,description,tags,category,hidden,slug`, tags separated by `|`,
  standard CSV quoting (`"Eggs, the right way"`). See `examples/demo-manifest.csv`.
- Rename, reorder or hide categories in the config: `"categories": { "cooking-tips": { "name": "Cooking", "position": 1 } }`.
- `./tube ingest` is incremental and idempotent: unchanged videos are skipped, changed ones re-encoded to a new
  versioned path, removed ones hidden on the site (`--prune` deletes their files). Works the same for 10 or
  1,000+ videos (`--jobs N` for parallel encodes).

## Configuration

`site.config.json` (written by `./tube init`) is validated against `site.config.schema.json`.
`site.config.example.json` shows every option with comments. Main switches:

| Key | Default | |
|---|---|---|
| `site.language` | `en` | `fr` or `en` (UI strings in `app/locales/`, override any of them with `strings`) |
| `content_label` | on, "AI-generated video" | disclosure label on video pages + badge; turn it off for non-AI niches |
| `private` | `true` | basic auth + noindex. Set `false` only when ready to go public |
| `ads.mode` | `placeholder` | `placeholder`, `off` or `live` (+ per-slot switches, VAST URL, house pre-roll) |
| `media_base` | `/media` | switch to a CDN host later without code changes (docs/ARCHITECTURE.md) |
| `deploy.target` | `ovh` | `ovh` or `ssh` |
| `deploy.prefix` | `<slug>-` | every cloud resource name starts with it; destructive commands refuse anything else |

Secrets never go in the config, only the **names** of files in `~/.secrets` (or `$TUBE_SECRETS_DIR`), mode 600:

| File | For |
|---|---|
| `ovh-api-token` | OVH API bearer token (target ovh) |
| `ovh-s3-access-key`, `ovh-s3-secret-key` | S3 keys of the media bucket (any provider: change the names in `deploy.storage`) |
| `<slug>-basic-auth` | generated by `./tube deploy`: the site password for user `viewer` |

## Hosting

### OVH Public Cloud (`"target": "ovh"`)

```bash
./tube bucket create && ./tube bucket sync   # private S3 bucket <prefix>media-xxxxxx, upload out/media
./tube up                                    # <prefix>web-1 (d2-4), region fallback, watchdog timer first
./tube deploy                                # app + media + Let's Encrypt; prints the URL
./tube status                                # box, health, bucket, watchdog, spend
./tube park                                  # done for now: snapshot + delete (idle = snapshot + bucket)
./tube up && ./tube deploy                   # back from the snapshot
./tube teardown                              # delete the box without a snapshot
```

- `deploy.ovh.project_id` and the token are all it needs. The prefix must be **unique per OVH project**: two sites
  in the same project need two prefixes.
- A **watchdog** (systemd user timer, `./tube watchdog status`) parks the box at `cap_minutes - 15` and deletes it at
  `cap_minutes` (default 6 h) so a forgotten test box can't run for a month. Raise the cap for a production site.
- Every command has `--dry-run`: real read-only GETs, prints each POST/DELETE it would make.

### Any Ubuntu server (`"target": "ssh"`)

Set `deploy.ssh.host`, `user` (root or passwordless sudo) and `port`, then `./tube up` (installs docker + ufw over
SSH with the same setup script the OVH boxes use) and `./tube deploy`. Media come from the bucket or, with
`"media_origin": "rsync"`, straight from `out/media` over SSH. `park`, `watchdog` and `cost` are OVH-only;
`teardown` stops the stack.

## Costs (OVH, EUR excl. VAT, list prices of 2026-10)

| What | Price |
|---|---|
| Web box d2-4 (2 vCPU, 4 GB, 250 Mbps) | ~0.02 /h, ~15 /month running 24/7 |
| Parked (snapshot of the box) | ~0.01 per GiB-month for the snapshot, a few GiB |
| Media bucket | 0.007 per GB-month, egress free |
| Load generator d2-8 (`./tube up --loadgen`, 90 min cap) | ~0.04 /h |

`./tube cost` prints the spend so far (OVH usage API + an estimate) and the monthly idle cost, from the live
catalog. One d2-4 handles roughly **20k daily users** (it is NIC-bound around 250 Mbps). Beyond that see
[docs/SCALING.md](docs/SCALING.md): CDN/edge media via `media_base`, managed Postgres, more app nodes, up to 10M daily users.

## Private by default

Until you set `"private": false`: HTTP basic auth on every page and file (fast `{SHA}` hash of a 24-character
random password, see docs/LESSONS.md), `X-Robots-Tag: noindex`, `robots.txt` disallowing everything, no sitemap
entries. Going public also means a legal notice (`footer.legal`), a cookie consent tool before real ads, and the
checks in docs/SCALING.md §6.
